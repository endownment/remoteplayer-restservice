# 11. Правила оформления кода

Правила, по которым написан код обоих проектов, и места, где Rust вынуждает
делать исключения.

## Типы всегда явные

У каждой переменной тип написан:

```rust
let listener: TcpListener = TcpListener::bind(address).await?;
let names: Vec<String> = files.iter().map(|file: &FileInfo| file.name.clone()).collect();
let (sender, receiver): (mpsc::Sender<Request>, mpsc::Receiver<Request>) = mpsc::channel(8);
```

- Параметры замыканий тоже аннотированы: `|file: &FileInfo|`.
- Нет `_` в типах (`Vec<_>`, `collect::<Vec<_>>()`): тип пишется целиком в
  объявлении переменной.
- Тип есть даже у игнорируемых результатов:
  `let _ignored: Result<(), Error> = sender.send(value);` — сразу видно, что
  именно мы игнорируем.

Где Rust не даёт написать тип, и как сделано:

| Место | Почему нельзя | Что сделано |
|---|---|---|
| `for item in collection` | синтаксис `for` не принимает аннотацию | тип виден по коллекции; при неочевидности — `let item: T = ...` внутри |
| образцы `match`, `if let Some(x)`, `while let` | в образцах аннотаций нет | тип задаёт сопоставляемое выражение, а оно аннотировано |
| замыкание в переменной (`let f = \|x\| ...`) | тип замыкания не имеет имени | такие замыкания заменены именованными функциями (`is_connected`, `edid_letter`, `meminfo_bytes`); замыкания живут только как аргументы |
| `let-else` | — | тип пишется: `let Some(line): Option<String> = ... else { ... };` |

## Комментарии

- Язык — только английский. Русского в коде нет нигде, включая строки и
  тестовые данные.
- Имена должны объяснять сами себя: `existing_folder_path`,
  `ensure_env_file_matches_current`, `wait_for_connection_after`.
- Комментарий пишется там, где поведение неочевидно: на границе с
  библиотекой (`DefaultBodyLimit`, `$VAR` в systemd, `CacheProperties::No`), где
  кроется ловушка (`aid` без аудиовыхода, `append` против `append-play`) или
  важна причина решения.
- Учебные пометки помечены префиксами: `// Ownership:` и `// Borrowing:` — где
  владение неочевидно, `// SAFETY:` — перед каждым `unsafe`. Длинные объяснения
  живут здесь, в dev-notes, а не в коде.
- Doc-комментарии `///` — у публичных функций, чьё поведение не следует из
  имени и сигнатуры.

## Инструменты

```sh
cargo fmt                     # rustfmt.toml: 120 колонок
cargo clippy --all-targets    # код держится без предупреждений
cargo test
```

`#[allow(clippy::...)]` допускается только с комментарием «почему». Пример —
`useless_conversion` в `MediaLibrary::usage`: на 64-битной платформе
преобразование лишнее, а на 32-битном ARM необходимо.

## Прочее

- Ошибки — свои enum через `thiserror` в каждом модуле, HTTP-статусы — только
  в `error.rs`.
- Закрытые наборы реализаций — `enum`, открытые — `trait`.
- Никаких `unwrap()`/`expect()` в коде сервиса. В тестах — `expect("что ожидали")`.
- Время и размеры — с единицами в имени: `restart_timeout_seconds`,
  `min_free_bytes`, `captured_at_unix_ms`.
